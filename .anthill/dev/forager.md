## Taste & reflexes

- **Pure detectors are the unit-test target.** Split each decision into a pure function over an in-memory manifest (`sniffStack`, `classifyUnit`, `internalDepsOf`, `parseWorkspaceGlobs`), then a thin orchestrator (`buildScanReport`) that does the fs reads. The pure functions pin the logic; a golden over a real fixture guards the wiring.
- **Emit through `agent-layer`, never raw.** `{ok,data,meta}` via `emit`/`emitError`; non-fatal notices go on `data.warnings`, never stderr in JSON mode. Guards emit, don't throw.
- **No dependency for one field.** pnpm workspace globs live in `pnpm-workspace.yaml` and Bun has no built-in YAML — I hand-parse the single `packages:` list rather than pull a yaml dep. Reach for a dep only when the parsing is real.
- **Deterministic ordering is a feature.** `stack` is dominant-first (meta-framework before base lib) so `stack[0]` is a stable primary-framework key and goldens don't flake. `Bun.Glob` is native — use it for tree expansion.
- **A pure guard proves the value; it does not protect the sequence.** `buildSeatLaunch` throws on an unsafe session key — but it's called _inside_ `spawn`'s pane loop, after `createSession`, so a raw throw there half-spawns (a partial tmux session + an unhandled exception). The guard on the pure fn is right, but the command body still needs its **own early preflight** (`SAFE_SESSION_KEY.test(config.channel)` beside the tmux check) so a bad value fails clean before any side effect. When a validated helper runs mid-side-effect-loop, guard the value at the helper AND gate the sequence at the top. (Pinned: `buildSeatLaunch` unsafe-key tests + the spawn preflight, commit `8a7471b`.)

- **Measure liveness by LAG AGAINST THE HEAD, never by the clock — a clock measures the traffic, not the wire.**
I was one step from deriving presence from wall-clock freshness of a stored position (`now - at`). It fails in the direction that matters: **on a quiet channel nobody's position moves, so every LIVE follower looks equally dead** — during exactly the silence where a real drop is hardest to notice. `head - emittedThrough` is 0 for every live follower regardless of traffic and grows only for one that has actually stopped consuming.
_Lesson, general past this feature: **when you build a liveness measure, evaluate it in the QUIET case first.** Quiet is when you will actually need it, and a metric that only behaves under load has been calibrated on the case that was never in doubt._ (Pinned: the `at: 0` still-`current` control — it fails if anyone "simplifies" this back to freshness.)

- **WE PIN WHAT A FUNCTION RETURNS AND NOT WHAT THE PROCESS EMITS — and the emitted artifact is the only part a consumer ever sees.**
Three independent cold reads in one session found defects **all at the same seam**, and the pure logic was correct in every case: the no-config branch dead and untested; `interpretFresh` exhaustively pinned while its projection into `data.fresh` was not; `toManifestEntry` pinned in both directions while the `.map` that calls it was not; and my own land string, where a `toContain` over the composed pieces passed against a string that was **a shell syntax error carrying backticks**.
The lead's framing was *"we test what a function returns and not what the process emits."* **The sharper version, which is the one that tells you where to look:** our seam between **COMPOSE** and **EMIT** has no test on the emit side, **so every assertion we write lands on the side that was already correct.** That is why the suite is green and the bug ships: we are not under-testing, we are testing the half that never broke.
_The remedy is a change of subject, not of coverage: assert over the **emitted artifact**, run through the thing that will actually consume it._ For a command string that means `bash -n`, not a substring. For a manifest it means the real emitted object's **key set**. **A substring is not usability** — that sentence cost this team a defect on every existing footprint.

F2 (prose concatenated into the command) and F2b (a piped `config.gate`) are genuinely one defect — an unvalidated string reaching a shell we tell a seat to run **verbatim** — so I fixed them in one change, correctly, with one verdict function. **I then assumed one assertion covered both.** It does not, and only mutation showed it: **`bash -n` is CLEAN on `bun run check | tail -6`.** A piped gate parses perfectly; it just tests the wrong command's exit status. ```

```
allow unsafe gates            → 1 fail (F2b only — bash -n STILL PASSES)
refuse every gate             → 3 fail (the positive anchors)
```
_Lesson: when you merge two defects into one fix because they share a cause, **mutate each one separately.** A correct unifying fix is exactly the thing that makes a blind assertion look sufficient — the code is right, the suite is green, and one of the two is unguarded. Measured by peers: that narrows the window to ~16s but does **not** close it, because the hook runs the gate a second time.
_The durable form: **your verification scope and your blast radius are different sets, and nothing shows you the second one.** `uncheckedAgainst` names dirty files outside your pathspec; it does not name whose land your tree state is currently refusing._
- **A "session key" that's really project-scoped is a bounded guarantee — state the scope, don't imply "anywhere".** sentinel's Phase 5 surfaced that spellbook derives the board id as `k-<keyname>-<projecthash>`, so both binding mechanisms I emit (the `.bounty-session` walk-up AND the `BOUNTY_SESSION_KEY` env key) only resolve from _within_ the project tree — the same exported key from `/tmp` gets "no session". Correct in practice (seats always run inside the repo), but a bound worth naming so no one assumes the env key binds a pane cd'd elsewhere. The mechanism nuance lives in `seams.md` Contract 3, not here. _Lesson: when you emit an ambient key, its resolution scope is part of the contract — name the boundary, don't let "session" read as "global"._ (Pinned: Contract 3 + sentinel's Phase 5 proof.)
- **Reading `main.meta.version` from a command means a circular import — and a top-level `await` in `cli.ts` turns it into a deadlock.** A command that needs the CLI's declared version has to reach back into `cli.ts`, but `cli.ts` eagerly builds its `subCommands` map, so a _static_ `import { main } from "../cli.ts"` evaluates `cli.ts` before the command's own binding exists → `ReferenceError: Cannot access 'teamFeedbackCommand' before initialization` (TDZ) the moment a sibling test imports the command. Two moves fix it together: **(1)** guard `cli.ts`'s execution with `if (import.meta.main)` + `export const main`, so importing it as a dependency doesn't run the CLI; **(2)** read the version via a _lazy_ `await import("../cli.ts")` inside `run()`, not a static import — deferring to call-time breaks the static cycle. **But** if `cli.ts` runs its entry via top-level `await runCli()`, the module sits forever in "evaluating" state, and the lazy self-`import()` waits on that evaluation → hard hang (no output, no exit). So the entry must run **detached** (`runCli().catch(…)`, not `await runCli()`) so the module finishes evaluating and the self-import resolves from cache. _Lesson: an entry file that other modules import for a value must (a) gate its side effects on `import.meta.main` and (b) never hold itself open on a top-level await._ (Pinned: `team-feedback.test.ts` imports the command with no cycle; a real `anthill feedback … --format json` run resolves `main.meta.version`.)

- **A SEAM INTRODUCED FOR TESTABILITY MUST BE PINNED TO THE PRODUCTION PATH, or it only MOVES the untested region.**
`resolveFormat` took the flag as a parameter and reached for the TTY as a global, so `Bun.spawnSync` (always a pipe) could never reach the TTY branch — *"a human at a terminal still gets usage"* was a shipped guarantee with **no automated guard**, hand-verified once with `script -q /dev/null` and never again. I made `isTTY` an optional second parameter, and then **every test I wrote passed it explicitly while all 21 production call sites use the default.** A hardcoded default would have left the whole matrix green and the real path unguarded — **the same shape as the bug the seam was added to fix.**
_Lesson: the assertion that matters is the one nobody thinks to write, because it looks like testing the language rather than the code: **the default is bound to the real source.** Mutation-check it — if hardcoding the default fails no test, your seam bought reachability and not coverage._ (Pinned: *"the DEFAULT reads process.stdout.isTTY"* in `agent-layer.test.ts`, commit `97fbee9`; mutation-checked to fail alone.)

- **A CORRECT TEST WITH A WRONG CONCLUSION IS NOT A WRONG TEST — read its rationale as evidence, not as an obstacle.**
A pre-existing assertion said *"a follower AHEAD of the head is `current`"* and I needed it to say otherwise. Its stated reason was a **real** race: a follower emits N while the head was snapshotted before that append. **The reason was right and the conclusion was wrong** — and treating that symptom as normal is exactly what let F1 hide (six seats reported `current`, gap 0, against `head: 0`, from records that outlived their log).
So the fix was to make the tolerated case **unreachable** rather than to keep tolerating or to delete the assertion: `comms positions` now reads **positions first, head second**, so the head is ≥ anything a position could have seen. The benign race can now only produce "behind by 1"; a remaining negative is genuinely impossible.
_Lesson: when a test blocks your change, the rationale is data. If it describes a real phenomenon, **your change is incomplete** — the test is reporting a case, not defending a bug. Closing the case beats both keeping and deleting the assertion._ (Pinned: the read-order comment in `team-comms.ts` + the revised test, `1edca84`.)
**SECOND INSTANCE, AND IT RUNS THE OTHER WAY — a test can LICENSE a defect on a rationale that is equally real.** _(Session 7, second stint; merged here rather than given its own bullet, because it is one lesson with two directions.)_ Above, a correct rationale **blocked** a correct change. In `b28c3b5` a correct rationale **blessed** a wrong one: *"a checked pid IS an observation."* True, and it authorised a teardown of live panes.
**So the instruction is symmetric and that is what makes it usable:** a test's stated reason is evidence about **the world**, never about whether its **conclusion** is right. When it blocks you, your change may be incomplete. When it agrees with you, it may be answering about a different object. **Either way you read the rationale and check it yourself — the one thing you may not do is treat the test's verdict as having done that for you.**

- **AN ADVISORY SIGNAL MAY PUSH TOWARD THE RECOVERABLE FAILURE, AND NEVER TOWARD THE OTHER.**
Contract 6(f) says `followerAlive` is advisory — pids are reused, it narrows a question and never answers one — which reads like *"do not make decisions with it."* But the teardown costs are **asymmetric**: a false *present* costs one `--force`; a false *absent* kills a seat mid-build. So the guard uses it in **one direction only — to say PRESENT, never absent** — and that is legitimate precisely because of the asymmetry.
_Lesson, general past this field: **an unreliable signal is still usable if you can name which direction its error runs and that direction is the cheap one.** State the asymmetry where the code is, or someone later "cleans up" the one-directional use into a symmetric one and it looks like tidying._ (Pinned: `commsPresence`'s one-direction rule, `fb85483`.)

  > **⚠ CORRECTION, and it is the most important thing on this page: WHEN I WROTE THAT, THE CODE DID THE OPPOSITE.** _(Session 7, second stint. Fixed in `b28c3b5`.)_
  > The principle above is **right** and I am keeping it. What was false was the sentence claiming the code implemented it. In shipped `fb85483`, `followerAlive === false` was neither `live` nor `unchecked`, so it **fell through to `{state:"none"}`** — and `none` is the only state `shouldBlockTeardown` permits teardown on. **The docstring, the commit message, and this lesson all asserted PRESENT-never-absent while the function said the opposite, on the command that kills panes.** A blank-context stranger found it; I had read this entry that morning.
  > **So the failure mode is not "I wrote a wrong lesson" — it is that a lesson, a docstring and a commit message are all PROSE ABOUT CODE written by the person who just wrote the code, and all three inherit the same wrong belief in one motion.** Three artifacts, three chances to catch it, **zero independence between them** — they are one claim written down three times, and their agreement is `principles.md`'s *agreement is not truth* with a sample size of me.
  > **The mechanical falsifier, and it is cheap enough that there is no excuse:** for any claim of the form *"X is used in one direction only"* / *"this can never return Y"*, **enumerate the branches and check the FALL-THROUGH.** The violating branch here was not a branch at all — it was the absence of one, and **a fall-through has no keyword to grep for**, which is exactly why it is the case that gets asserted about and never tested.
  > _The durable form: **prose is not evidence about code, even when the same person wrote both — especially then.** Pin the claim to an assertion that fails when the claim goes false, or do not make the claim._ (Pinned: *"a dead follower is UNKNOWN, never absence — down kills panes, not followers"*, `b28c3b5`; mutation-checked to fail against the old code.)

- **NAME THE OBJECT AN OBSERVATION IS ABOUT, NOT WHETHER IT IS TRUE — a true premise about the wrong object is how a defect gets blessed by a test.**
The test that licensed the bug above was called *"a dead follower is absence — a checked pid IS an observation"*. **Every word of that premise is true.** A checked pid IS an observation — of a **follow process**. The verdict it fed is about a **seat**, and the command it authorises kills a **pane**. Three different objects, one true sentence, and the conclusion is wrong at every join.
The fix was one line of reasoning that a future maintainer can actually apply, so it went in the code rather than here: **`down` kills PANES. `followerAlive` observes FOLLOW PROCESSES. A follow process is not a pane.**
_Lesson: when a test's name argues for its conclusion, check what its evidence is **about** before checking whether it is **true** — truth is the cheap half and it is the half that survives review. Contract 6(f) had already ruled that a dead pid means the position is a high-water mark and not that the seat is gone; I had a contract I own saying the opposite of my own test, and neither the contract nor the test moved for a session._
**The corollary that saved the fix from being worse than the bug:** the obvious repair — treat every uncertainty as presence — **removes `none` entirely**, and a guard that always blocks trains reflexive `--force`, which deletes the guard for real. So only a **total absence of records** reaches `none`. **When you harden a guard, check that its permissive verdict is still reachable**; an unreachable safe-state is a guard people learn to bypass, and that failure is invisible because the code looks strictly safer.

## Anti-patterns

- **A fixture that exercises the mechanism but not the representative case.** My first workspace fixture had one app depend on the shared package (fan-in 1) — it proved `internalDeps` _computes_, but the consumer's contract-seat path needs fan-in ≥2, so the one fixture meant to represent the motivating case represented its opposite. sentinel caught it. _A green golden can be correct-but-unrepresentative; make the fixture look like the real target._
- **Throwing from a detector.** A missing member dir or an unparsed glob is a `warnings[]` entry, not an exception — the command must still emit a usable envelope.

- **A test that generalizes from a COMPLETE set.** `team-join.test.ts` asserted "every line starting with `Monitor` contains `--line-buffered`". That was true of the only two wires that existed, so it read as an invariant about _wires_; it was actually an invariant about _greps_. The first filter-free wire made it false, and the suite bounced correct code with full authority. _A test written when the set is complete encodes the set, not the rule — key it on the thing that actually causes the requirement._ (Sub-trap that cost two cycles: I re-keyed on the substring `"grep"`, which then matched my own no-filter warning **prose** and the checklist line quoting `tail --from-start | grep` as the anti-pattern. **Matching prose that discusses a command is indistinguishable from matching the command.**)
**Second instance, same seat, same day — so this is a habit, not an accident.** Enforcing the emitted-not-read seam, I asserted that the staleness error never contains the word `read`. It failed against my own string, because the error emits the recovery command `anthill comms read --since 1` — I had matched the **command name**, not a claim. **Banning a WORD is not banning a CLAIM**, and the vocabulary you want to forbid always also appears in the tool's own affordances. Key the assertion on the proposition (`you have read`, `since you last read`), never the token. _Both instances happened while writing a test FOR an honesty rule, which is when the temptation to grep for a word is strongest._

- **Leaving a decision unstated in a contract.** `comms read` is identity-free on purpose — identity binds the verbs that _attribute_ (`send`, `follow`), not the ones that observe. But I never wrote that down, and a cold read couldn't tell the decision from an oversight. _An unstated decision and a gap are identical from outside; if you chose it, say you chose it._ (Pinned: Contract 4 clause (c-bis).)
