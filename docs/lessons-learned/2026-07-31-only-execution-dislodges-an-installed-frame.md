# An installed frame survives its own repair attempts — only execution dislodges it

**Date:** 2026-07-31
**Tags:** `#multi-agent` `#epistemics` `#skill-authoring` `#anti-pattern`
**Type:** Pattern
**HiveMind:** captured as scenario `only-execution-dislodges-an-installed-frame`

---

## The Lesson

An instruction does not just supply a command — it installs a **frame**, an assumption about what
_kind of object_ the answer is. Repair attempts then search inside that frame, because a frame is
invisible from within: it defines what counts as a candidate.

> **When your second and third fix live in the same family as your first, you are inside a frame.
> Stop tuning and go run something.**

The question that breaks it is not "what is a better X" but **"is the answer an X at all"** — and it
is reliably answered by execution, never by another round of reasoning, because execution is the only
cheap operation that touches something the frame does not control.

## The instance

Interviewing the story-loom team required a **blind condition** — each seat answering before reading
its peers'. The instruction named `pull`, which prints a channel from message one, so the first seat's
answer contaminated everyone downstream. The fix was `--since 11`; it behaved exactly as documented and
leaked anyway, because a forward-open range over a channel peers are actively writing to will
eventually contain a peer's write. Three attempts in total, all range expressions.

`read <channel> <id>` fetches exactly one message. Not a narrower window — **not a window.**

- **calvino** had used it **thirteen times** that session, his most-used grapevine command. Told to run
  `pull`, he ran `pull`. Twice — the second time _after_ posting a message diagnosing what `pull` did.
- **shahrazad** had the same habit and spent an hour on three broken range fixes while holding it.
- **aesop** used it unprompted and was the only genuinely blind respondent in either round.

shahrazad diagnosed four of his own session errors as one move: range → tighter range; defending a
summary **phrase** rather than re-opening the option set; refining an **argument** built on a grep
count instead of reading the two rows it summarized; checking his **wording** when challenged rather
than the claim.

> _"Iterate within the frame, don't test the frame."_

**The tell was uniform** — every frame-break came from an agent who **ran something**: calvino running
the command and noticing what he'd been reading all session; aesop running a scan and diffing file
counts; hurston grepping the whole tree instead of within the scope boundary everyone was reasoning
inside.

## The diagnostics

Three signatures, all portable:

- **A better-worded version of the same claim comes back.** The revision changed the wording, not the
  substance.
- **Someone found a workaround.** Treat that as a reason to keep diagnosing, not a resolution — a
  working workaround is exactly what removes the pressure to test the original claim. (tolkien
  mis-typed `read` once, concluded the tool was broken, and reported it as defective **twice**, with a
  correct usage string unread in his scrollback.)
- **A summary stands in for its source** — a count, a phrase, a preview — and the challenge is answered
  by improving the summary rather than opening what it summarized.

## Corollary for eliciting anything

**Ask what they did, not what they want.** Preferences are generated inside the frame and will agree
with it; behaviour is generated by contact with the world and can contradict it.

The worked example is our own: the standing hypothesis was that seats got **too many messages**, and it
was shaping a proposed debounce/bundle design. Asking for behaviour — how many did you fetch in full,
did a batch ever cost you your place — falsified it. Notifications arrive _between_ tool calls rather
than interrupting one, so there was no interruption cost to remove. The premise was dropped.

## Caveat (load-bearing)

This is **not** an argument that deliberation is always wrong. Plenty of claims have no runnable
invariant — architecture calls, naming, priorities. For those the honest move is to say the agreement
is about prose and name what would change your mind, not to manufacture a command to run. Let a
**same-family repair sequence** trigger the check; don't adopt a blanket preference for doing over
thinking.

## What this is _not_ evidence of

Worth stating, because it is the natural over-read and we made it ourselves first: this is **not**
evidence that agents treat agreement as truth. Nobody here converges on a false claim — calvino ran
`pull` because he was instructed to, not because peers endorsed it. That flocking claim may well be
real, but it rests on other evidence and needs its own instance. See
[what would count](../backlog/2026-07-31-storyloom-round-three-at-first-dev-work.md).
