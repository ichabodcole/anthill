# Taxonomy pass 1 — anthill's own team, 2026-09-03

**What this is.** Before the first curation run, Cole asked for a meta-analysis of the migration
report batch (`.anthill/reports/2026-09-03-migration/`): is there a classification of the _kinds_ of
thing seats wrote down, and what would a fix for each kind look like? The answer may become the
"what class is this?" step of the curation method.

**How it was produced — blind, independent, then merged.**

- Seven fresh agents, one per file (six seat reports; the retro and paper-cuts logs together). Each
  was told only that the material came from an AI agent holding one seat on a multi-agent software
  team over many sessions. None saw anthill's design, the proposal, the routing menu, or each
  other. Each inventoried every item with an id and a verbatim anchor, grouped the items into
  classes of its own naming with a defining test, and for each class proposed an intervention in its
  own words, judged specificity (seat / project / any team), and counted recurrence.
- One further fresh agent read only the seven outputs and produced `MERGED.md`: a unified taxonomy
  with every source class mapped exactly once, convergence counts, boundary disagreements, size,
  interventions, specificity votes, and residue.

The prompts asked _what happened_ and _what kind of thing is this_, never _which of these buckets_
— per the observer-effect note in this project's memory: a primed question finds what it was primed
for.

**Files.** `MERGED.md` is the result. `source-<file>.md` are the seven blind passes, kept so the
merge can be checked against them and so a second pass (Spellbook, blind) can be compared.

**Numbers.** 1,392 items inventoried across 8 files (about a quarter marked as repeats). 63 source
classes → 14 unified classes + 3 residue items. Class sizes and source-support are in `MERGED.md` §1–3.
