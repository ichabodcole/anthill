Seven classes. Every item is in exactly one. No "unclassified" residue was needed — the two items I hesitated over (C96 wrong word in a table; C98 chasing your own message) sit in classes 1 and 5 respectively without strain.

Splits I was tempted by and did not make:

- Splitting class 1 by error shape (adjacent measurement / invented cause / misattribution / unit-denominator / staleness / bad control). The author's own repeated verdict is that these are one defect "wearing a new hat", and the epitaph lineage is the record of trying and failing to carve them. Splitting would reproduce that argument, not classify.
- Merging class 2 (guard failures) into class 1. The author explicitly separates "the claim was wrong" from "the guard was present, correct, and did not operate" (s9 rationale, C15), and the prevention differs: class 1 wants a check on the claim, class 2 wants a change to when/where the check runs.
- Merging class 7 (epitaph slot) into class 6 (document hygiene). Both are about the doc, but an epitaph is a distilled warning plus a judgment about which warning holds the slot; hygiene is about pointers and edits. Different consumers.

### 1. Own-claim errors with the mechanism named

Test: an item belongs here if it records a concrete instance where a specific claim, number, attribution, remedy, or wording of the author's was false or one step from being published false, and states the mechanism that produced it.

Members (38): C6, C7, C10, C13, C16, C24, C25, C26, C31, C34, C39, C45, C53, C57, C59, C61, C63, C67, C68, C73, C76, C81, C82, C84, C85, C87, C88, C89, C90, C91, C92, C94, C96, C99, C101, C103, C104, C111.

Prevention / usability: the material is unambiguous that re-reading does not catch these and peers do. Two interventions follow. (a) A send-time gate in the messaging tool: when a draft contains a number, a person's name next to an artifact, a causal connective ("because", "so", "which means"), or an absence word ("zero", "none", "nobody"), refuse it unless the sentence carries a `[checked]`/`[assumed]` tag, a sha stamp, and — for counts — one line stating what one unit is and the command that enumerated it. Runs in the harness on `comms send`, not in the agent's head; the author's own conclusion is that dispositions fail at the recognition step. (b) A "second reader" step at finalize: any sentence naming a person or a commit is handed to a peer who re-runs the command (`git show <sha>:<path>`, the grep with a positive control) before the report is landed; the author's evidence says three of four omission gaps were found by people running the instruction, none by reading it. Usability for the next agent is the harder problem: 38 near-identical incidents are unreadable as a checklist. A curated form would be one table — error shape, the one question to ask, the one command to run — with the incidents as footnotes.

Specificity: the shape (measuring the adjacent thing, inventing a cause) is generic to any agent that publishes claims. The sting is seat-specific: this seat's outputs are claims about colleagues, so a wrong number is an allegation. Any agent team will hit the shape; only a measurement/observer role hits the consequence.

Recurrence: 4 explicit repeats (C59/C15, C63/C13, C82/C6, C99/C16). Beyond literal repeats, the author counts n=4, n=5, n=6 instances of the same shape inside single sessions, so nearly every item here is a recurrence of the class even where the wording is new.

### 2. How guards, tags, and checks fail to operate

Prevention / usability: the author's own diagnosis is that the failing variable is the MOMENT — a guard read at grounding is not held at the instant it applies, an outward-aimed guard is never turned inward, a tag applied from intent is hollow. The intervention is to bind each guard to the action it protects instead of to the doc: a hook that prints the relevant clause when the triggering command runs (the `--as-of` hazard text at the moment `--as-of` is typed; the "did you measure this noun" question when a send names a person), and a self-application step at finalize ("list the three guards you applied to peers this session; show one application to your own output"). Owner: the harness for the hook, the seat's finalize checklist for the self-application step. Specificity: generic. Nothing here depends on the project or the seat; any agent maintaining a living doc of its own failure modes will hit "the guard was there and did not fire".

## Notes

- Readability with no context: hard. The prose assumes a vocabulary (`--as-of`, `waitedMs`, `uncheckedAgainst`, `seams.md` Contract numbers, `principles.md` scars, seat names, message ids like `#660`) and a shared history of thirteen sessions. I could follow each item's internal argument, but I could not tell without the lineage which items were live and which were retired, and in the Candidates section the ~~strikethrough~~ status plus a quoted superseded block plus a fresh paragraph made it slow to find the current claim. Emphasis is near-universal (bold in almost every sentence), so it stops carrying information.
- The file has a strong internal consistency: the author repeatedly catches, in-doc, the exact defects the doc warns about (the count that rotted, the line ref that rotted, the retracted claim still standing, the guard applied outward). That is the material's most reliable signal and it argues for mechanical intervention over more prose — the author says so too.
- Attribution to peers is scrupulous (steward's form, forager's wording, weaver's rule; "say whose it is"). A curator merging this batch with other seats' reports will find the same items recorded from the other side.
- Several Hard-won lessons carry a status marker that a curator needs: FIXED UPSTREAM (C37), fixed at `51ec81e` (C116), built `f8a7bd8` (C118), RULED by the human (C123), FALSIFIED (C110, C127), SUBSUMED (C115). These are the items that should not be re-raised.
- Quantity is not the same as distinctness. 145 items collapse to roughly 124 distinct records, and class 1 collapses further: the author's own count of "one shape" instances suggests the file holds perhaps a dozen distinct mechanisms told forty times. That is a property of the recording practice (one entry per incident) rather than a flaw in any entry.
- One place the material contradicts itself and does not say so: C107 (Candidates) still recommends "stamp the time you ran `git status`" while C81 (Hard-won lessons) reports that remedy falsified on the author. A register with status would have caught this.
